# Remediation log — security audit (2026-11-13, branch `security-audit`)

Every code change made during the audit. Nothing was deployed; no production data or configuration was changed by
these fixes (migration `0003` is unreleased; `0002b` is a standalone file the owner can apply).

| ID | Severity | Files | Root cause | Fix | Regression test |
|---|---|---|---|---|---|
| AUD-01 | High | `supabase/migrations/0003_clinic_portal.sql` | `clinic_patients` required `user_id` and `linked_at` to be both null or both set. Deleting a linked patient's auth account sets `user_id` to NULL (ON DELETE SET NULL) but not `linked_at`, so the whole deletion failed and `/api/account` reported `accountDeleted: false`. | Constraint relaxed to `user_id is null or linked_at is not null` (link time kept as history). | `tests/db/clinic-security.test.ts` › account deletion (reproduced failing first: `violates check constraint "clinic_patients_check"`) |
| AUD-02 | Medium | `src/app/api/account/route.ts` | A clinic owner deleting their account cascaded away the only owner membership, leaving the clinic and its patients' records with nobody able to administer them. | Account deletion is refused (409, nothing deleted) while the user actively owns a clinic. | Covered by API fuzz/authorization suite (route behaviour); manual review |
| AUD-05 | High (clinical safety) | `src/lib/domain/sanitize.ts`, `src/lib/domain/text.ts` | The sanitizer verified only *numbers* in medication fields against the source excerpt. A weak free model was observed writing its own reasoning into a frequency field ("twice a probably need … Actually …"); it would have reached review looking like transcribed text. | Medication text fields (dose, route, frequency, timing, duration, special instructions) with ≥3 content words absent from their excerpt are removed and flagged `unsupported_value`. Common dosing paraphrases are tolerated. | `tests/unit/sanitize-wording.test.ts` (real observed output, invented instruction, faithful fixtures unaffected) |
| AUD-06 | Low | `0003_clinic_portal.sql` | The daily retention job cleaned up abandoned *patient* uploads only; clinic uploads stuck in `uploading` were never removed. | `run_retention()` also deletes clinic documents stuck in `uploading` for 24 h. | `tests/integration/migration.test.ts` (static), pgTAP suite |
| AUD-07 | Medium | `0003_clinic_portal.sql`, `src/app/api/clinic/versions/[id]/route.ts`, `src/app/api/clinic/plans/[id]/route.ts`, plan page | Any staff member (including nurses) can update a *draft* plan's bundle directly through the Data API (needed so AI processing started by a nurse can save), bypassing the API's clinician-only edit rule without attribution. Drafts are not patient-visible and approval is reviewer-only, but the edit left no trace. | `plan_versions.last_edited_by` set by trigger on every content change, and a `plan.content_changed` audit entry with the editor's role — written in the database, so every path is covered. Forging `last_edited_by` is refused. The review page shows "last changed by". Duplicate API-level `plan.edited` log removed. | `tests/db/clinic-security.test.ts` › draft edits are attributed |
| AUD-08 | Medium | `src/app/api/extract/route.ts` | The anonymous demo extraction endpoint had only a per-client limit; many clients together could exhaust the shared free-tier AI quota. | Additional overall cap (60 per 10 min per server instance). | API fuzz suite (no 5xx) |
| AUD-09 | Low | `src/lib/api/route-utils.ts` | The shared route wrapper caught Next.js's internal control-flow errors (dynamic-rendering bail-out during build) and logged them as "unexpected error" 500s. | `unstable_rethrow(err)` before mapping errors (per Next.js docs). Build no longer logs the spurious errors. | Build output (0 occurrences, was 2) |
| AUD-10 | Low (hardening) | `0003_clinic_portal.sql` | The notification `link` check accepted `//host` (protocol-relative, off-site). Not exploitable: only database functions create notifications and users cannot edit links. | Check now rejects `//…`. | Migration applies in PGlite suites |
| AUD-12 | Medium (clinical safety) | `src/lib/domain/conflicts.ts` | Contradictions *within one document's activity advice* were detected only if the model reported them. Promptfoo showed the model (Gemini 3.1 Flash-Lite) consistently missing "avoid lifting > 5 kg for 6 weeks" vs "return to weight training after 2 weeks" — both shown as normal instructions. | Deterministic rule: a restriction and a permission on the same topic (lifting/strain, driving, bathing/swimming, exercise/sport, sexual activity) raise an open conflict flag; items become "conflicting" and block approval until resolved. Errs towards flagging. | `tests/unit/activity-conflicts.test.ts` (observed output; no false alarm on the normal summary); Promptfoo re-run 4/4 with the live model |
| AUD-13 | Medium | `src/lib/api/route-utils.ts`, `src/app/api/clinic/organization/route.ts`, `src/app/api/clinic/patients/[id]/route.ts`, `src/app/api/clinic/documents/[id]/route.ts` | PATCH bodies with no editable fields passed validation and sent an empty update to PostgREST, which failed with a 500 (found by the API fuzzer: 5 requests). | `requireChanges()` drops absent fields and returns 400 "There is nothing to update." Applied to all three partial-update routes. | `tests/live/api-fuzz.spec.ts` (re-run) |
| AUD-14 | Low | `next.config.ts` | Nuclei: `X-Permitted-Cross-Domain-Policies` missing. | Header set to `none`. | Nuclei / header tests |
| AUD-11 | Info | `src/components/auth/password-forms.tsx`, `src/lib/gemini/prompts.ts` | Two Semgrep false positives (client-side "passwords match" comparison; the word "patient" in prompt text matched a hard-coded-username rule). | Annotated `nosemgrep` with justification so Semgrep can gate CI with `--error`. | `semgrep scan --error` → 0 findings |
